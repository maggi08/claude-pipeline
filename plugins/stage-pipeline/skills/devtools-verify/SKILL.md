# DevTools Verify — рантайм-чекер

Цель: проверить, что реализованный этап **реально работает в браузере**. Ты — проверяющий: ищи падения и расхождения, ничего не чини (починка — fix-loop оркестратора в /stage-check, у него живой HMR).

**Запуск — субагентом `devtools-verify`** (`${CLAUDE_PLUGIN_ROOT}/agents/devtools-verify.md`, модель дешевле оркестраторской). Смысл: снапшоты/скриншоты/сеть/консоль — самые тяжёлые артефакты в сессии; в субагенте они живут в его контексте и умирают вместе с ним, а наружу уходит компактный отчёт. Разделение труда с оркестратором: **субагент наблюдает → оркестратор чинит → короткий повторный прогон субагента только по починенным пунктам** (dev-сервер и HMR-цикл держит оркестратор).

> **Project config.** Dev-URL, команды и `<task_dir>` — из `<repo>/.claude/pipeline.config.md` (нет файла — `/pipeline-init`). Ниже `<dev-url>` = `dev server.url` из конфига, `<task_dir>` = `task_path`.

## Предусловия

- Тулы `mcp__chrome-devtools__*` доступны (загрузить через ToolSearch). Нет — отметь skip и сообщи, что нужен `/mcp reconnect chrome-devtools` или новая сессия.
- **MCP-профиль занят** (сервер есть, но браузер не поднимается: Chrome-профиль MCP держит другой процесс): проверь владельца по цепочке процессов (`ps` → родитель до claude/IDE). Чужая ЖИВАЯ claude-сессия — её Chrome НЕ убивать; осиротевший Chrome (родитель мёртв) можно снять. Занято живой сессией → fallback: `playwright-core` из node_modules репо + системный Chrome — `chromium.launch({channel: 'chrome', headless: true})`, скрипт в scratchpad; методология та же (computed-замеры JSON'ом, скриншоты по путям). Проверено на IT-5236.
- Dev-сервер: URL и команда старта — из конфига (`dev server.url`, `commands.dev`). Проверь `curl -sk <dev-url>/`. Не запущен — подними в фоне командой из конфига и дождись 200. (Пример mycar: `https://localhost:3001`, `yarn dev`, HTTPS self-signed.)

## Auth-гейт

Флоу за обязательной авторизацией (OTP по реальному номеру) агент пройти не может. Два режима:
- **Залогиненный управляемый профиль** (предпочтительно): Chrome-профиль MCP персистентен между запусками — пользователь один раз логинится в управляемом окне руками, дальше агент гоняет auth-gated сценарии сам. Проверка на старте: открой auth-gated роут и посмотри, есть ли редирект на логин; профиль залогинен — работай как обычно.
- **Профиль не залогинен**: НЕ пытайся проходить OTP. Auth-gated критерии помечай `[live: user-side]` в отчёте (секция «Не удалось проверить») — их закрывает пользователь на user-review. Проверяй всё, что ДО гейта (редиректы на /auth, unauth-состояния, консоль).
Реальность KC-463: почти все live-проверки этапов 11–21 упирались в гейт и уходили пользователю — режим с профилем экономит этот цикл.

## Процедура

1. **Открыть страницу**: `new_page` → URL этапа (`<dev-url>/<route>`), `resize_page` 1440×900.
2. **Консоль** (`list_console_messages`, types: error, warn) — сразу после загрузки:
   - `Hydration ... mismatch` — critical (SSR/client расходятся; частые причины: несколько корневых узлов с ClientOnly, стор, инстанцированный на сервере, отдаёт payload вместо localStorage — лечится Pinia `hydrate`-хуком).
   - `ReferenceError` — critical (обычно неимпортированный вложенный composable — [[core-nested-composables-not-autoimported]]).
   - Игнорируй легаси-шум: Amplitude defaultTracking warn.
3. **Скриншоты light и dark**: Chrome по умолчанию dark. Light: `emulate` colorScheme light + `evaluate_script` `document.documentElement.classList.remove('dark')` (тема сайта живёт своей жизнью, после reload повторить). Сверь light-скрин с Figma-скрином глазами: структура, состояния кнопок, иконки. Dark сверять не с чем (Figma light-only) — ищи только явные поломки (карточка слилась с фоном, нечитаемый текст) и фиксируй как вопросы.
4. **Ширины**: `resize_page` 1280 и 1024 (+ ширина, на которой пользователь жаловался, если была) → скриншот на каждой: наезды блоков, схлопнувшиеся элементы (фиксированные px-паддинги!), горизонтальный скролл.
5. **Живое состояние**: подготовь стейт через `evaluate_script` (напр. `localStorage.setItem('classifiedCreate.draft', JSON.stringify({step: 1}))` + reload) и проверь критерии приёмки этапа: восстановление драфта, переходы шагов, disabled-состояния. Клики/ввод — `click`/`fill` по uid из `take_snapshot`.
6. **Анимации/переходы — computed-числами, не «глазами»**: для каждой анимации из критериев сними через `evaluate_script` `getComputedStyle(el).transitionDuration/transitionDelay/transitionTimingFunction` (и `animationDuration`) и сравни С ЧИСЛАМИ дизайн-источника — «что-то анимируется» не вердикт. Computed `0s`/дефолт при классе в исходнике = несгенерённый Tailwind arbitrary-value (плагины дублируют `duration`/`delay`/`ease` → `delay-[220ms]` молча дропается; IT-5236: фейды сплэша шли дефолтными 150ms с первого этапа и прошли все статические сверки). Поимённый список подозрительных классов приходит из proto-compare (секция «Не удалось проверить») — закрой каждый. Динамику (сработал ли переход в нужный момент) — поллинг computed-значений с таймстампами; два скриншота с интервалом — только грубый fallback.

## Экономия контекста

Приоритет по «тяжести» артефактов (от лёгкого к тяжёлому): `evaluate_script` (JSON) → screenshot jpeg q60 → screenshot PNG → `take_snapshot` (a11y-дерево). Всегда выбирай самый лёгкий, который отвечает на вопрос.

- **`evaluate_script` с компактным JSON (числа/booleans) — первичный инструмент замеров.** Паддинги, gap, размеры, disabled, наличие класса, значения драфта — всё это числа/флаги, а не скриншот. Скриншот ради замера — антипаттерн.
- **Скриншот — только для глазной сверки структуры с Figma.** 1 финальный PNG на стейт. Промежуточные (ширины, до/после фикса, dark-санити) — `format: "jpeg", quality: 60`.
- **`take_snapshot` (тяжёлое a11y-дерево) — только когда реально нужен uid для `click`/`fill`.** Не дампи снапшот «на всякий случай».
- **Снипет-гигиена evaluate-проб**: классы читай `el.getAttribute('class')`, не `el.className` (у SVG это SVGAnimatedString — `.includes` кидает TypeError); grep по скомпилированному CSS — с пробелом после двоеточия (`transition: opacity …`, Tailwind эмитит значения с пробелом — grep без пробела даёт ложный «класса нет»).
- В субагенте всё это остаётся в его контексте; в оркестратор идут ПУТИ к скриншотам и компактный отчёт, а не кадры и не дампы.

## Отчёт

Формат как у figma-compare: таблица | # | Элемент | Проблема | Ожидалось | Реально | Severity | Где |. Severity: падение/пустая страница/hydration = critical; сломанный layout на поддерживаемой ширине = major; визуальный шум = minor. Скриншоты сохраняй через `take_screenshot` filePath в `<task_dir>/<TICKET>/checks/screens/`. Обязательная секция «Не удалось проверить».

Найденные первым прогоном классы багов (реальные кейсы KC-463): hydration mismatch от двух корневых ClientOnly; драфт игнорировался из-за SSR-инстанцирования стора (Pinia hydrate); прогресс-бар с px-[480px] схлопывался на 1024; тёмная тема без dark-макета.
