# Сообщение коммита этапа

Читается из `/stage-check`, Шаг 4.4, и `/stage-force`, Шаг 1.6.

Заголовок: `<TICKET>: <что сделано>` — одна строка, до ~72 символов, в настоящем времени и по сути изменения, а не по номеру этапа. «`<TICKET>`: автофокус и отложенная валидация полей ввода» — годится; «`<TICKET>`: этап 29» — нет: через месяц по такому сообщению нельзя понять, что искать в истории.

Тело добавляй только когда заголовок объективно не вмещает суть: 1–3 строки про **почему**, не про «что» — что видно из дифа, в теле не повторяют.

Стиль сверяй с историей репозитория (`git log <main_branch> --oneline -20`): где приняты префиксы типа `feat:`/`fix:` — следуй им, где нет — не вводи.

**Не добавляй в сообщение служебные подписи** — ни `Co-Authored-By`, ни строку о генерации инструментом, ни эмодзи-маркеры авторства. Это решение пользователя для всех его репозиториев: история должна читаться как написанная человеком, который отвечает за изменение. Если такая подпись добавляется автоматически (шаблон, хук) — убери её из сообщения этапа.
