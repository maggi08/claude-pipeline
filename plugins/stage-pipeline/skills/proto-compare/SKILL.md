# Proto Compare — сверка кода с прототипом

Цель: найти все расхождения между прототипом (HTML/CSS + SPEC.md) и реализацией. Ты — **проверяющий**, не автор: не оправдывай код, ищи расхождения. Ничего не чини — только отчёт.

> **Project config.** Пути, источники правды и `<task_dir>` — из `<repo>/.claude/pipeline.config.md` (секции «Design sources of truth» — поля `design_source`, `design_snapshot`, `spec`, `tokens`, `ui_lib`, `breakpoints`, `i18n` — и «Checker overrides»; нет файла — попроси запустить `/pipeline-init`). Методология сверки та же, что у `${CLAUDE_PLUGIN_ROOT}/skills/figma-compare/SKILL.md` (токен-first, severity, text fidelity) — этот скилл описывает отличия файлового дизайн-источника от Figma MCP.

## Вход

- Фича/этап → флоу-файлы прототипа и screen-id (если не даны — найди по таблице «prototype file → spec section» в шапке SPEC.md).
- Пути к коду (страница/компоненты). Если не даны — из `<task_dir>/<TICKET>/FEATURE-MAP.md` или по роуту.
- Контекст/форм-фактор (mobile / desktop / встраиваемый виджет / kiosk и т.п.) — у прототипов обычно отдельные файлы на форм-фактор.

## Источники правды

**Сторона дизайна** (прототип-репо, путь `design_source` из конфига):
- `SPEC.md` — поведение: стейты, переходы, CTA decision-таблицы, тайминги, guard-условия. Screen-id таблицы = реестр хэшей `flow-*.html#screen-id`.
- `flow-*.html` + CSS флоу — визуал: структура, значения, классы. Читай точечно (grep по `id="screen-id"`, блок экрана), файлы большие.
- Прототипы обычно построены на токенах проекта — CSS-переменные совпадают с приложением; проверяй по `tokens` из конфига.

**Сторона кода** (из конфига): `tokens`, `ui_lib` (+ дефолтные стили компонентов ui-lib — обёртки добавляют свои паддинги), `breakpoints`, локали `i18n`.

## Порядок сверки

1. SPEC.md: секция фичи → список экранов/стейтов и ожидаемое поведение.
2. HTML/CSS: по каждому screen-id — структура и значения (классы → CSS-правила).
3. Код: классы/стили/пропсы компонентов ui-lib. Разрезолвь в значения.
4. Сравни по чеклисту, элемент за элементом, сверху вниз.

## Чеклист

Всё из figma-compare-чеклиста: **цвета на уровне токенов** (прототип `var(--x)` ↔ в коде соответствующий токен/класс, сырой hex в коде = critical), **типографика**, **отступы/gap**, **границы/радиусы**, **тени**, **размеры/порядок элементов**, **структура/состояния**, **компоненты DS** (самодельная копия при существующем ui-lib-аналоге = critical), **dark mode** (токен несёт dark-вариант сам).

Специфика прототип-источника:
- **Поведение по SPEC.md — статически проверяемая часть**: наличие переходов (роуты/обработчики), CTA-лейблы и их условия (decision-таблицы), guard-условия, состояния ошибок/empty/loading. Тайминги и анимации статически НЕ проверяются — в слепые зоны (devtools-verify).
- **Hex в самом прототипе** (без CSS-переменной): сверяй значение и проверь, нет ли подходящего токена в DS — если есть, в коде должен быть токен (а расхождение прототипа с DS отметь как вопрос дизайнеру).
- **Proposal vs current**: если у фичи два варианта прототипа — какой сверяем, должен сказать промпт/STAGES.md. Неясно → эскалация, не выбирать молча.
- **Sync-контракт**: HTML ↔ SPEC.md расходятся — зафиксируй как вопрос дизайнеру (нарушение контракта прототип-репо), не выбирай молча, сверяй по обоим с пометкой.
- **Свежесть источника**: конфиг объявляет и внешний `design_source`, и коммитнутый в репо `design_snapshot`, и они расходятся по нужному флоу → правда во внешнем; отметь расхождение в отчёте.

## Text fidelity

- **Статическая копия** (лейблы, кнопки, заголовки, хинты, empty-state, ошибки) — посимвольно: тире/кавычки/`…`/nbsp. Источник — текст HTML (не скриншоты, vision не нужен).
- **Мок-данные** (имена, названия, даты, счётчики, цены) — НЕ сверять значения, только формат, если он специфицирован.
- **i18n**: язык копии прототипа = эталонная локаль. Сверяй с РАЗРЕЗОЛВЛЕННОЙ строкой этой локали из `i18n` конфига, не с ключом. Захардкоженная строка вместо хелпера перевода = critical (если проект многоязычный). Для остальных локалей — проверь наличие ключа.

## Severity

Как в figma-compare: **critical** — не тот токен/hex вместо токена, отсутствующий/лишний элемент/экран/переход, самодельный компонент вместо ui-lib, захардкоженная копия без i18n; **major** — spacing/radius/shadow/типографика > 2px, неверное выравнивание, неверный CTA-лейбл/условие; **minor** — ≤ 2px, шрифтовый рендеринг.

Не флагай: мок-данные, длину текста, картинки-заглушки, скроллбары, антиалиасинг, **служебный хром прототипа** (floating nav, scenario chips, event console, design/embed toggles — это инструменты прототипа, не дизайн).

**Слепые зоны статики** — перечисляй в «Не удалось проверить»: тайминги/auto-advance/анимации (SPEC их специфицирует — проверяет devtools-verify, которому прототип можно открыть в браузере рядом с приложением для side-by-side), hover/focus, responsive-поведение между брейкпоинтами, реально сгенерированные CSS-классы.

**Arbitrary-values ≠ скомпилированный CSS.** Класс в исходнике — не гарантия, что утилита попала в бандл: Tailwind молча дропает arbitrary-values, которые считает неоднозначными (плагины вроде tailwindcss-animate дублируют `duration`/`delay`/`ease` → `delay-[220ms]`/`duration-[280ms]`/`ease-[…]` не генерируются; та же история бывает с `shadow-[var(…)]`). Урок IT-5236: фейды «прошли» статическую сверку по именам классов, а реально шли дефолтными 150ms. Поэтому каждый arbitrary-value transition/animation/shadow-класс из дифа перечисляй ПОИМЁННО в «Не удалось проверить» как обязательный runtime-пункт для devtools-verify (computed-значение, не наличие класса).

## Выход: отчёт

`<task_dir>/<TICKET>/checks/proto-compare-<stage>.md` (нет task-дира — просто выведи).

```markdown
# Proto compare: <flow-файл#screen-id> ↔ <файлы кода>
Вердикт: PASS | N расхождений (X critical / Y major / Z minor)

| # | Элемент | Свойство | Прототип | Код | Severity | Где |
|---|---------|----------|----------|-----|----------|-----|
| 1 | CTA «Continue» | цвет фона | var(--primary) | bg-[#385bf8] (hex) | critical | src/pages/X/Btn.tsx:12 |

## Поведение (SPEC §N)
(переходы/CTA-условия: что совпало, что нет)

## Не удалось проверить
(тайминги, hover, sync-расхождения и т.п. — честно перечисли)
```

Каждая строка — с точным `file:line` и точным значением из прототипа. Расхождений нет — явный PASS со списком проверенного.
