# Гигиена контекста — вся задача, не только проверка

Контекст — главный расходник. Замеры, на которых стоят правила ниже: `chrome-devtools` MCP дал ~49% дневного usage, пока рантайм-проверка шла в оркестраторе; 82–91% расхода — на сессиях >150k контекста; за четыре дня 177M cache-read токенов, из них 98M за один день-марафон, средний контекст запроса 234k.

- **Сырые дампы Figma не живут в главном контексте.** Спеку для реализации этапа собирает субагент `figma-spec` (`${CLAUDE_PLUGIN_ROOT}/agents/figma-spec.md`, в прототипных репо — `proto-spec`): ему — node-id и путь `<task_dir>/<TICKET>/specs/<stage>.md`, назад — компактная таблица (структура, токены, размеры, стейты). Прямые вызовы `get_design_context` из оркестратора — только точечно, когда субагентский цикл дороже (один маленький компонент).
- **Рантайм-дампы (chrome-devtools) — тоже не в оркестраторе.** Наблюдение гонит субагент `devtools-verify`; в оркестратор идут пути к скриншотам и компактный отчёт. Если пришлось звать chrome-devtools напрямую (перепроверка в fix-loop или fallback без агента) — **`/compact` сразу после**, не дожидаясь конца этапа: снапшоты и скриншоты вымываются, пока не накопились.
- Скриншоты Figma/браузера в оркестраторе — по минимуму: 1 на экран для глазной сверки; остальное внутри субагентов. Замеры — `evaluate_script` (числа), а не скриншот.
- Закрыл этап → `/clear` (дефолт) или `/compact`, если в этой сессии осталась связанная работа (`/stage-check`, Шаг 4.5). **`/clear` при переходе на несвязанную задачу** (новый тикет, ретро, отдельный баг) — не тащи контекст предыдущей.
- Большие трекеры читай точечно — текущий этап через offset/grep, а не файл целиком. Закрытые этапы и старый журнал сворачивает `scripts/archive-stages.mjs` (`/stage-check`, Шаг 4.2); хук SessionStart напоминает, когда STAGES.md перевалил за 40 KB.
- **Открытые вопросы дизайнеру/продукту — в один трекер** `<task_dir>/<TICKET>/DESIGN-QUESTIONS.md`, а не по одному в журнал каждого этапа: так они закрываются батчем, а не переоткрываются на каждом шаге (формат года, порядок плейсхолдеров, чекбоксы согласия всплывали повторно).
